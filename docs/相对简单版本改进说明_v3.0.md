# GovEnt-AgentShield v3.0 相对简单版本的改进说明

## 1. 对比范围

本说明以原简单版 `GovEnt-AgentShield(5).zip` 为基线，同时吸收全面版 `GovEnt-AgentShield 11(2).zip` 的认证、权限、审批、执行和审计能力。v3.0 的目标不是把页面堆得更复杂，而是保留简单版“选案例—点检测—看结果”的使用方式，同时让每个绿色或红色结论都有真实后端链路和测试证据支撑。

## 2. 最重要的架构修正

简单版的主链是：

```text
用户输入 -> Input Guard -> Tool Guard -> 最终决策
```

全面版虽然增加了 MultiSource Guard，但原实现顺序实际是：

```text
用户输入 -> Input Guard -> Tool Guard -> MultiSource Guard -> Policy/Registry
```

这会导致单个来源均看似正常、组合后才形成攻击的请求先进入 Tool Guard。v3.0 改为：

```text
用户输入
  -> 单条输入检测
  -> 网页/文档/RAG/记忆多来源关联
  -> 输入总门禁
       ├─ review/block：立即短路
       └─ allow/warn：进入可选Skill准入
  -> Skill准入通过
  -> Tool Guard
  -> RBAC/ABAC、任务链、注册表、审批、受控执行
```

门禁失败时，结果中的 `stage_status` 会明确记录：

```json
{
  "tool_guard": "skipped_by_input_gate",
  "policy": "skipped_by_input_gate",
  "task_chain": "skipped_by_input_gate",
  "registry": "skipped_by_input_gate",
  "execution": "skipped_by_input_gate"
}
```

这不是页面上的说明文字，而是运行时真实返回值，并由 `tests/test_gate_ordering.py` 强制验证。

## 3. 功能对比

| 能力 | 简单版 | v3.0 完整版 |
|---|---|---|
| 页面使用 | 页面较轻，单条输入容易操作 | 保留简单交互，并新增默认“一键安全检测”首页 |
| 单条输入 | 规则、评分、编码解码 | 保留并增加双层URL编码、HTML实体、Unicode零宽字符覆盖 |
| 多来源输入 | 没有来源级关联门禁 | 来源信封、逐源扫描、共享编号/字段关联、拆分语义重组、内容指纹 |
| 拆分攻击 | 只能命中单条文本中的完整攻击句 | 覆盖敏感对象与外传动作分离、绕过词与审批对象分离、Base64跨来源分片 |
| Skill | 单Python文件静态扫描 | 输入通过后才允许运行时Skill准入；同时保留独立包级供应链扫描 |
| 工具调用 | 检测工具名称和参数 | 只有输入与Skill门禁通过才进入；再叠加策略、任务链和执行注册表 |
| 身份权限 | 无强制身份控制 | 服务端Token身份、RBAC/ABAC、密级、环境和可信目标域名 |
| 审批 | 无完整状态机 | 禁止自批、请求指纹、到期校验、一次性消费、批准后再验策略 |
| 执行 | 主要输出检测结果 | 白名单本地适配器；无任意Shell和任意外部网络执行入口 |
| 审计 | JSON结果 | 敏感字段脱敏、追加式SHA-256哈希链和完整性验证 |
| 测试 | 单模块与基础集成 | 门禁顺序、困难攻击、API、审批、任务链、供应链和一键案例统一回归 |
| 交付体积 | 小包含Git历史和大量开发输出 | 不含`.git`、`.venv`、缓存和开发期日志，可干净重建环境 |

## 4. 保留的简单版优点

1. 保留中文政企场景和明确的四级决策：`allow / warn / review / block`。
2. 保留人工Skill样例的细粒度区分，不把所有 `open()` 或 `import os` 都粗暴判成恶意。
3. 默认首页不要求手写JSON。用户选择案例并点击一次即可看到测试是否通过。
4. 详细JSON、审计、审批和评测仍保留在专业页面，不挤占默认演示流程。

## 5. v3.0 新增的困难攻击识别

- 三来源编号映射外传：`F-27 -> demo_private.txt -> validation -> /audit`；
- 敏感对象和外传动作分散在不同文档；
- 绕过词、审批/权限对象和执行动作分散在不同来源；
- Base64危险载荷被切成两段分别放入文档和网页；
- 双层URL编码和HTML数字实体；
- 零宽字符、全角字符和标点插入；
- 附件白色文字、页脚、批注和RAG间接指令；
- 伪造管理员身份和免审批授权；
- 跨来源长期记忆/知识库延迟投毒；
- 安全分析与真实执行请求的上下文区分，降低关键词误报。

## 7. 需要诚实说明的边界

工程回归集用于证明代码、门禁顺序和既定攻击类型不会在修改后退化，不是外部独立盲测。正式参赛仍应由未参与规则开发的成员制作冻结盲测集，并在规则冻结后揭示标签。规则和AST静态分析也不能证明系统能识别所有未来攻击；生产环境应增加本地语义模型、制品签名、CVE数据源、企业身份系统和远程不可变审计。
